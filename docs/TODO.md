### Bug review of the trading path — Completed ✓
- [x] Baseline: `tsc --noEmit` clean + 191 tests green before any change 2026-09-14  
- [x] **Bug 1 (critical) — a mistyped `--config` silently traded the LIVE account.** `loadConfig` guarded the CLI overlay with `if (overlayPath && existsSync(overlayPath))`, so a typo or a renamed profile was ignored without a word; `config/local.json` is `mode: "live"` with live T212 credentials, so asking for the paper profile placed real orders (violates AGENTS.md "never auto-switch to live mode"). Verified: `loadConfig({overlayPath:"config/paper-real-dtaa.json"})` returned `mode: live`. Now throws `ConfigurationError`; the CLI also rejects `--config` with no value 2026-09-14  
- [x] **Bug 2 (high) — a rejected run killed the whole `pnpm serve` process.** `PipelineScheduler.check()` is fire-and-forget with no `catch`, so any rejection from the orchestrator prologue (reconcile / sweep / DB) became an unhandled rejection → Node terminated the process, taking the scheduler AND the dashboard down 2026-09-14  
- [x] **Bug 3 (high) — the economic gate saw a frozen snapshot.** `DecisionService.decide` passed the pre-run `heat` and `snapshot.cash` to every intent, so up to `maxOrdersPerRun` (3) BUYs each passed against the untouched start and *collectively* breached `maxHeatPct` (3×500 on 10 000 NAV: heat 0.54 → 0.69 against a 0.6 cap) and the cash limit (2×400 from 500). It also made a sell-funded rebalance impossible (`INSUFFICIENT_CASH`). Fixed by threading a running `availableCash`/`runningHeat` through the loop 2026-09-14  
- [x] **Bug 4 (medium) — `allocationTargets.current()` returned several rows per ticker.** `WHERE updated_at = (SELECT MAX(updated_at) … WHERE b.ticker = a.ticker)` matched the whole latest batch (a session writes every target with one `now`), returning duplicate tickers with different weights → duplicate drift rows, `sum > 1` invariant could throw. Fixed with `ROW_NUMBER() OVER (PARTITION BY ticker ORDER BY updated_at DESC, rowid DESC) = 1` 2026-09-14  
- [x] **Bug 5 (medium) — T212 precision retry could overshoot the gate.** Half-up rounding sent 13 shares for an approved 12.5 (+4%) and 0 for 0.4 (an impossible order); now floors toward zero and fails `unsupported` when the size floors to 0 2026-09-14  
- [x] **Bug 6 (medium) — Finnhub `debtToEquity` was always null** (`totalDebtTotalEquityQuarterly` does not exist; the real key is `"totalDebt/totalEquityQuarterly"`, verified live) and **`marketCap` was in millions** while the demo adapter used units — the analyst prompt read a $4.85T company as a $4.85M micro-cap 2026-09-14  
- [x] **Bug 7 (medium) — a 429 on order submission permanently lost the trade.** Nothing retried a rate-limit failure although a 429 proves no order was created, contradicting AGENTS.md ("treat new 429s as transient"). Now retried once inside `submitOrder` 2026-09-14
